# 反思：第一性原理

用於定期維護、任務回顧，或評估某個規則、方法是否該改。結果是**候選**，不是已採納的變更；「不變更」是正當結論。

## Deconstruct

- 用一句話重述目標：要解決的實際問題，而不是目前的做法。
- 把內容分成三欄：**事實**（附來源）、**假設**、**未知**。

## Challenge

- 為每個假設尋找反證：哪些證據會證明它錯？
- 對每個限制標出性質（技術、成本、政策、偏好、習慣）與**誰能核准改變它**，各限制分開判斷。
- 標出哪些未知會改變結論，哪些不會。

## Reconstruct

比較至少三個選項：

| 選項 | 內容 | 成本 | 維護負擔 | 可逆性 | 風險 |
|---|---|---|---|---|---|
| 現況 | 不變更 | | | | |
| 最小改善 | | | | | |
| 替代方案 | | | | | |

推薦一個選項並說明理由，列出需要的核准者（owner decision 或提案 review）。

## 紀錄

在 [reflections/candidates.md](../reflections/candidates.md) 追加：

```markdown
## [YYYY-MM-DD] <標題>
- 觸發：
- 事實／假設／未知：
- 選項與推薦：
- 需要的核准：owner decision | 提案 review | 無（不變更）
- status: candidate
```

狀態：`candidate` → `proposed`（已建提案或請 owner 決定）→ `adopted`／`rejected`／`no-change`。被拒絕的候選保留理由，不刪除。
